# Nationwide free shipping

Admin's “უფასო მიწოდება” toggle saves `products.free_delivery` through the existing allowlist-protected product writes. Enabled products ship for 0 GEL anywhere in Georgia. They add no chargeable weight, including in mixed carts and above 1000 kg. Weight may be left blank for free delivery; paid delivery still requires valid weight and the existing selected-type tariff. A delivery type and address remain required for fulfillment, including free orders.

All-free carts hide the delivery type selector and display “მიწოდება — უფასო (0 ₾)”. Checkout supplies the existing valid `city` type internally for these orders; the server still independently verifies actual product flags and calculates zero shipping nationwide. The customer must still supply the delivery city and address. Paid/mixed carts show the selector above subtotal, delivery, the existing divider, total and checkout button. They require an explicit selection unless a previous paid-delivery selection remains in the same cart session. No backend or SQL change is needed for this UI behavior.

The cart labels each free product, and checkout explicitly shows free delivery and 0 GEL for all-free carts. Mixed carts show the charge for paid products only. Missing paid-product weights continue to block checkout with a clear error. The database total weight sums known weights using `COALESCE(weight_kg, 0)` so missing free-product weights cannot propagate NULL. Thus all-free orders with no known weights record total weight 0; mixed orders retain the sum of known weights. Item snapshots preserve missing weights as NULL. The browser continues to label the full physical weight unknown if any weight is missing.

The migration is ready for manual execution after its prerequisites, based on static review and non-SQL tests. Database execution remains unverified under the no-SQL instruction. `node tests/free-shipping-migration.cjs` verifies the prerequisite column, NULL-safe arithmetic, free/paid/mixed cases in all four destination types, and that the remaining RPC logic matches the original weight-shipping migration.

Manually apply `supabase-nationwide-free-shipping.sql` after the existing product-delivery, weight-shipping and Admin-security migrations. It replaces only the six-argument checkout RPC, retaining server-only execution, authoritative locked product reads, stock reservation, immutable snapshots, receipt idempotency and customer ownership. The existing `free_delivery` column already exists in `supabase-product-delivery.sql`; no new product column is necessary. No historic order or product data is rewritten. Admin cancellation/restoration and customer RLS are unchanged.

The browser's expected free flag and weight are confirmation guards. The database uses the actual product flag; a customer cannot obtain free delivery by changing the request. A missing weight is accepted only for a database product with free delivery enabled. No shipping rates or payment integration were changed.
